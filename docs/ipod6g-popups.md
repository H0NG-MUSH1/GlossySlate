# Popups in the Glossy Slate style

As of 11 November 2026. This file describes the current code in the
repository (`IPOD_6G`).

Rockbox drew messages as a white box with a black frame in the UI viewport
of the skin (in menus only the left 160 px), and yes/no questions as text
in the list area. Now every popup is a dark glossy panel like the tiles,
with a shadow, centred on the whole screen. Design: the handover from the
UI design (`GlossySlate/firmware-assets/popups/README.md`). A skin cannot
style popups, so this is done in the firmware.

## Kinds

| Kind | Rockbox | Panel (W × H, without shadow) | Content |
| --- | --- | --- | --- |
| message, 1–5 lines | `splash()`, `splashf()` | text + 28, 120–240 wide; 24 + 16 per line high | lines from y 12, spacing 16, centred |
| message with symbol, 1–2 lines | the same, for known messages | text + 28, 132–240; 104 / 120 | symbol 48 × 48 at ((W − 48) / 2, 16), lines from y 74 |
| progress, 1–3 lines | `splash_progress()` | text + 28, 208–240; 24 + 16 n + 16 | lines from y 12, bar at (14, 12 + 16 n + 8), W − 28 wide |
| yes/no, 1–3 lines | `gui_syncyesno_run()` | 240; 80 + 16 n | question from y 12; buttons "Yes" (blue) and "No" (slate), 102 × 26 each at x 14 and 124; below them "Center button" / "Other button", with a time limit followed by the time left |
| letter of fast scrolling | `popup_letter()`, from `tree.c` (database) and Cover Flow | 112 × 112 | one letter (A–Z, #) 72 px in `#DFE6F3`, see [ipod6g-fast-scroll.md](ipod6g-fast-scroll.md) |

The panel lies at `x = (320 − W) / 2`, `y = (240 − H) / 2`. Lines break at
212 px at spaces and line feeds; a word that is too wide on its own is cut
off. Text 13 px bold white, button hints 11 px bold `#C5CFDD`. The answer
after a yes/no question and "Timeout" are messages.

Symbols per message (language ID that `splashf()` gets):

| Symbol | Messages |
| --- | --- |
| check mark | Settings Saved, Reset done |
| warning | Database is not ready, failed, Bookmark Failed |

All other messages are plain messages without a symbol, "Bookmark Created"
too. The loading circle of the design (12 frames) does not exist: a message
like "Loading…" is drawn once while the caller works, so the circle could
not turn. Info, lock and open lock from the design are not built in.

The key lock shows no popup when locking and unlocking (nor when a key is
pressed while the keys are locked). The theme shows the lock: the lock in
the status bar or the lock screen (`apps/action.c`, `do_softlock()`).

### Picture parts

For every height (40, 56, 72, 88, 96, 104, 112, 120, 128) the panel is
split into three parts: the left end, 26 wide with the shadow, the middle,
1 px (the gradient is vertical, so it is repeated), and the right end. The
right end is the left one mirrored (the PNGs differ by at most 4 of 255),
so only the left one is stored. The bar (track 9 high with a light edge,
fill 8) and the buttons are made of three parts as well; a fill narrower
than 8 px shows only its left end, cut off on the right.

Every part is RGB565 with 8 bit alpha. `popup.c` blends it with the frame
buffer itself, with a 4 × 4 ordered dither like the cover effect
(`skin_albumart_fx.c`). With the 4 bit alpha of the skin engine the soft
shadow would show visible steps.

### The screen below

Before drawing, `popup.c` saves the area under the popup including the
shadow (at most 264 × 153 px) and afterwards remembers a checksum of the
area with the popup.

- `popup_close()` restores the area if it still looks exactly the same
  (nobody has drawn over it). This happens after messages with a duration
  and at the end of every yes/no question.
- When a popup is drawn again (progress up to 20 times a second, yes/no
  with the time left, repeated messages), the old one goes first, so the
  shadow does not get darker. If the new one has another size or position,
  the area of both goes to the display. Before, the display got only the new
  one: a narrower popup (such as "Building database… 360 found", whose width
  changes with the number) left the shadow of the previous one standing on
  the left and right, on the display only, not in the frame buffer and not
  in a screen dump.
- "Boot file changed / Reboot now?" after unplugging USB (`check_bootfile()`
  in `apps/misc.c`) stands on an empty screen: `gui_syncyesno_run_blank()`
  leaves the theme out during the question and clears the screen. Before,
  the yes/no question drew the status bar skin with an outdated title when
  it switched the theme on, and on the left there were still remains of the
  USB screen. After "No" the theme comes back and is drawn completely; "Yes"
  reboots.
- After "Database is not ready / Rebuild" `root_menu.c` no longer clears the
  list (`clear_screen_buffer()`, only needed for the old dialog that wrote
  into the list). The list stays under the progress popup.
- Messages without a duration stay until the caller redraws, as before. As
  long as the popup is untouched the status bar skin does not draw (it
  would paint over the part on the sidebar). If someone has drawn over it,
  such as the list, the skin redraws completely the next time and so also
  removes the rest on the sidebar (`popup_screen_state()` in
  `sb_skin_update()`).

`popup.c` reads and writes the pixels directly in the frame buffer of the
display (`lcd_framebuffer_default`), not through the viewport that happens
to be set. `popup_screen_state()` does not touch the viewport at all. Only
for the text (`putsxyf()`) and for `lcd_update_rect()` (which takes the
pixels through the buffer of the current viewport) a viewport is set
briefly, and the caller's one is set back afterwards.

### Freeze (fixed)

The first version made the iPod freeze, right after start or later while
using it. The cause was `draw_text()`: it passed an uninitialised
`struct viewport` from the stack to `viewport_set_fullscreen()`. That
function starts with `init_viewport()`, which reads `vp->buffer` and, if the
pointer is not NULL, checks and writes `stride`, `data` and `get_address_fn`
through it. With leftovers on the stack that was a random address: foreign
memory was overwritten, with an immediate or a later effect depending on
its content. `viewport_set_defaults()` sets `vp->buffer = NULL` beforehand
for exactly this reason. Now the text viewport is static and its buffer is
NULL before the call.

Narrowed down on the device: without popups (`GS_POPUPS 0`) no freeze; with
popups but without the check in `sb_skin_update()`, still freezing. Proven
on the Mac: a test (`popup.c` with stand-ins for the Rockbox functions)
aborts with the old `draw_text()` as soon as the stack was used before
(buffer pointer `0x7000000ff`), and not with the new one.

Note for building: the make dependencies do not know `popup.h`. After
changing it, `touch` `splash.c`, `yesno.c`, `statusbar-skinned.c` and
`root_menu.c` so that they are compiled again.

### Speed

| Place | before | now |
| --- | --- | --- |
| blending with alpha (shadows, edges) | 3 divisions by 255 per pixel; the iPod's ARM9 has no divide instruction, each is a library call | multiplication and shift, exactly the same for every value that occurs (checked) |
| middle of the panel, the bar, the buttons (1 px wide, repeated) | one call per column, a bounds check and an index per pixel | one row at a time: opaque as a fill, otherwise blending without an index |
| redrawing at the same place (progress up to 20 times a second, time left of yes/no) | write the area back and save it again (copying up to 80 KB twice) | only write it back; the saved copy holds the same content already |
| text of `splashf()`, answer after yes/no | 256 bytes on the stack | static, like `splash_buf` in the old code |

The result is the same pixel for pixel: the test draws panels of every
height and width, bars and buttons of every width at many places over random
pixels, old and new; in 2434 cases no difference. It also checks for every
kind of popup (long words, umlauts, many lines, empty texts, progress
outside 0..100 %) the bounds of the frame buffer and of the saved copy, that
after closing the screen is the old one pixel for pixel, and that the
caller's viewport is set afterwards.

Found and fixed on the way: a yes/no question without a question line gave
a panel 80 px high, for which there is no picture part; the 88 part was
drawn, 8 px beyond the saved area. An empty question now counts as one empty
line (96 px).

### Memory

Reserved once at start, nothing at run time from the playback buffer: the
picture parts 100 KB (program), the saved area 80 KB, the text of
`splashf()` 2 × 256 bytes. `font_load_ex()` shares the fonts with the skin,
which loads them anyway.

## Checking on the device

| What | Look for |
| --- | --- |
| message over the list and the sidebar | soft shadow, everything back after closing |
| locking/unlocking the keys | no popup, only the lock in the status bar (or the lock screen) |
| creating a bookmark (stop in a podcast/audiobook) | "Bookmark Created" without a symbol, one line |
| rebuilding the database | progress without flicker, the shadow does not get darker |
| yes/no (e.g. "Database is not ready / Rebuild") | center button = yes, other button = no, then the screen as before |
| long message | line break at 212 px, at most 5 lines |
